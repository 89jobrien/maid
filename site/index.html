maid

Sorts a directory into subfolders by file type, turns documents into markdown with frontmatter, and quarantines anything a secret scan catches before it reaches the vault.

How a file is claimed Source
maid / preview ~/Downloads
$ maid preview ~/Downloads
==> /Users/joe/Downloads

Preview - no files will be moved:

 invoice.pdf -> CONVERT (mutool) -> invoice.md + archive
 photo.jpg  -> ~/Downloads/images/photo.jpg
 notes.md   -> QUARANTINE (~/.local/share/maid/quarantine)
 script.py  -> ~/Downloads/code/script.py

4 file(s) would be processed, 0 noted in place.

The action ladder

maid run applies one action per file in a fixed order, and the first match wins. What matters is not where a file ends up but which rule claimed it first.

01 note The category's action is note and the file is older than its stale threshold: archive it as YYYYMMDD-<name>. Otherwise leave it in place and count it as noted.
02 convert The extension appears in a convert list: convert to markdown, inject frontmatter, secret-scan the result, and archive the original. Clean output lands in the notes destination.
03 notes gate Markdown is scanned by obfsck redact --audit. A match quarantines the file; a clean result gets frontmatter and moves normally.
04 move Everything else goes to its category destination. This is the fallback, so it claims whatever the first three rungs declined.

Rung 3 is the only one that can put a file somewhere the caller did not ask for. Quarantine is a different destination, not a severity level on the others — which is why it is the one rung in its own hue.

Safety

maid moves real files, so most of its behaviour is a refusal to move them badly.

0 Hidden files touched
1 Directory deep, never recursive
1000 Name attempts before failing
1 Undoable run per directory
RuleWhy it is there
Never overwrites A taken destination becomes name-1.ext, then name-2.ext, up to 1000 attempts, then the run fails.
Undo never overwrites either A restore conflict reports and stops, leaving a loud partial state, because a partial state is recoverable and a silent overwrite is not.
Hidden files and subdirectories Skipped entirely. Scans are one level deep.
Per-move journal Each move is recorded as it finishes, so a run that dies partway still leaves a replayable record.
Gate errs open, not closed If obfsck is missing or its verdict is unreadable, maid warns and treats the file as clean — failing closed would quarantine every note.

Configuration

~/.config/maid/config.toml, falling back to the platform config directory. Every table is optional; stock defaults apply.

TableControls
directoriesWhat to process when no path is given. Defaults to Documents, Downloads, Desktop.
categoriesExtension to folder. Matched case-insensitively, unknown as fallback.
destinationsAbsolute targets per category, including quarantine and archive.
convertWhich extensions go through pandoc, mutool, or marker, and the fallback when marker is absent.
actions / staleWhich categories are noted rather than moved, and after how many days.

Do not list one extension under two categories. The table is keyed by extension, so a duplicate resolves to whichever category is inserted last — and category iteration order is not deterministic.

Commands

CommandEffect
maid preview <path>Prints the resolved final path for every file. Moves nothing.
maid run <path>Applies the ladder and journals each move.
maid undo <path>Reverses the most recent run in that directory.
maid completionsEmits a Nushell completion script.

The recommended loop is three commands: preview, run, and undo if the preview was wrong. Preview cannot fully predict conversion, because whether the generated markdown trips the secret gate depends on a file that does not exist yet — so it says so rather than promising a destination.
